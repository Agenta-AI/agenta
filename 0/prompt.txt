## Credential selection design

Every tool request now reads the credential immediately before it sends. There is one source per turn: a runner-only `ToolCallbackRuntime { endpoint; credential: () =&gt; string | undefined }` in `src/tools/run-credential.ts`. `runTurn` builds it once per turn and passes the same object to `startToolRelay` and to `buildApprovedContentWiring`, which passes it to the config-text fetcher. `ToolCallbackContext` in `protocol.ts` is unchanged. There is no property getter named `authorization`.

`startToolCallbackRuntime` picks the credential this way:
- **Session-owned turn:** it reuses the watchdog lease only if that lease started from the same value as `toolCallback.authorization`. The watchdog starts from `platformCredentialForRequest(request)`, so I compare that value with the callback credential.
- **Standalone turn with Agenta ingest:** it reuses the existing lease in `runTurn` on the same condition (that lease starts from `runCredential(request)`).
- **Any other turn** (no watchdog, no tracing, an external collector, or a different credential): the turn starts its own lease from `toolCallback.authorization`. The refresh goes to the base of `toolCallback.endpoint` with `/tools/call` removed. That is the origin that already receives this credential, so the refresh sends it nowhere new. The turn releases the lease in its `finally` block.
- **No credential in the callback:** the getter returns `undefined` and no lease starts.

Why: the comparison is the simplest rule that can never send an external collector key on a tool call or into the refresh. The collector key can only be selected when it is equal to the callback credential. Warm sessions get a new runtime each turn, and it is never stored on the pooled environment.

- `message`: "The platform credential for this turn expired."

The error's message is the JSON of this envelope. Every path that turns a thrown error into tool text therefore carries the envelope.

## What the tests cover

- **Rotation:** one relay; the credential changes from A to B; direct calls, callback calls, search and config-text reads all send B.
- **Credential selection:** with no tracing, the turn refreshes the callback credential against the callback base. With an external collector, `Bearer collector-key` never reaches a refresh or a tool call. A session lease that holds the same credential is reused, and no second lease starts. On a warm session, the next turn gets a new runtime with its own credential.
- **Expired 401:** an ordinary tool, a callback tool and search all return the envelope. On the approved-content read, both the gate path and the relay path return it.
- **Unchanged cases:** these keep today's errors: a 401 with another reason, a 401 with a non-JSON body, a 401 with a string detail, a 403 that names `expired_signature`, and a transport failure. Search still returns `tool_search_unavailable` for a 500. Approved content still returns `source_base_unavailable` for a 401 with `invalid_token`.
- **Mutation checks:** I broke the turn-owned lease and the reuse of the watchdog lease. The selection tests failed both times.
