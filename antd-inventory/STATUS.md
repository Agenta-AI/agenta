## Tailwind v4 — readiness, not dependency

shadcn's default target is now Tailwind v4; this repo is on **3.4.19** (v3 is still a
supported shadcn path). We are **not** migrating Tailwind as part of this work, for a
specific reason: preflight is disabled _because of antd_ (see the comment on `corePlugins`
in `oss/tailwind.config.ts`). Migrating to v4 now means doing it with antd's reset still
fighting Tailwind's, preflight still forced off, across 554 files and 2116 `border`
usages with no visual-regression coverage — and then partly redoing it once antd is gone.
**This project is what unblocks v4.**

What actually differs between shadcn-on-v3 and shadcn-on-v4, and how each is handled:

| Difference                                     | Kind                       | Status                                                                                                                                                         |
| ---------------------------------------------- | -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No `forwardRef`, `data-slot` attributes        | **React 19**, not Tailwind | ✅ done — all primitives                                                                                                                                       |
| Where tokens live (`@theme` vs `theme.extend`) | config location            | ✅ isolated to `controlScale` + `shadcnTokens`; the v4 move is one file, class names unchanged                                                                 |
| Renamed utilities                              | class vocabulary           | ⚠️ **exactly 2 in the new layer**: `outline-none` (→`outline-hidden`) and `ring` (default width 3px→1px). Greppable; the whole v4 sweep for `ui/` is these two |

Rules that keep it that way — **do not** hardcode pixels/hex in a component (use the
`control-*`/`btn-*`/`input-*` scale and the token bridge), and don't add a utility whose
meaning changed between v3 and v4 without adding it to the table above.

## Decisions (resolved)

- **Real shadcn, always.** Components are built from actual shadcn/ui source (Radix primitives,
  `cva`, shadcn's prop API) — not an antd-shaped API wearing Tailwind. When a feature antd had
  doesn't exist in shadcn (`allowClear`, `Input.Search`, `autoSize`), the answer is a **composed
  component built on the `@agenta/ui` primitive**, never "leave this one on antd". A
  `components.json` is checked in so the shadcn CLI _could_ scaffold a starting point, but shipped
  `@agenta/ui` components are hand-authored (Radix + cva) and re-skinned — NOT registry pulls.
- **No extension props on primitives.** Button has no `icon`/`loading` — icons are children
  and `LoadingButton` is a composition, as in stock shadcn. Everything antd-only was dropped
  and re-expressed as a composed component.
- **No raw pixels or hex in a component.** Geometry/type come from `controlScale`, colour from
  the `shadcnTokens` bridge (both in `oss/tailwind.config.ts`). This is also what keeps the
  Tailwind v4 move a config change rather than a component rewrite.
- **Scope:** primitives now, domain later.
- **Migration tactic:** facade-first — reimplement preset internals over the `@agenta/ui` component (no call-site edits, no visual change), clean up call-sites/delete later.
- **info color:** unified on antd navy (`#1c2c3d`/`#1668dc`). ⚠️ ~11 custom `bg-colorInfo` consumers now render navy not blue — verify in-app.
- **default/outlined chip bg:** antd's opaque dark flatten (`#272727`) baked into `palette.fill.chip` → `--ag-colorFillChip` (a translucent var can't match antd's pinned opaque).
- **Radius NOT bridged into the global scale:** overriding `theme.borderRadius` would change
  every `rounded-*` in the app. Control radii live in the additive `control-*` namespace
  instead (`rounded-control`, `rounded-control-round`).

## Learnings / gotchas

Full symptom→cause→fix reference: **[GOTCHAS.md](GOTCHAS.md)** (read before implementing a new component or touching the harness). Highlights: don't alias react/react-dom (forks React); preflight-off needs `border-solid`; match antd's EXACT per-mode value (it pre-flattens fills to opaque in dark); measure ground truth in-browser, not generated CSS; completing `--ag-*` never touches antd config; restart SB only for main.ts/tailwind.config/deps.

> **Headless :focus limitation.** `:focus`/`:focus-visible` engage only when the OS window has
> focus, so _programmatic_ `.focus()` sets `activeElement` but not the pseudo-class — you must
> drive focus with a REAL click/Tab via the browser tool. Synthetic events also can't focus the
> antd side, which is why the antd Select's open-glow couldn't be live-diffed; its values are
> taken from antd's exact `controlOutline` token.

> **Earlier "13/13 MATCH" claims for Input were wrong.** They came from an ad-hoc snippet that
> did not compare `font-family` or `width`. Writing the check as a committed script immediately
> surfaced a real bug it had been hiding: with preflight off, our `<input>` rendered in **Arial**
> and our `<textarea>` in **monospace** instead of Inter. Fixed with `font-[inherit]`; the
> property is now part of the snapshot so it cannot regress silently.
