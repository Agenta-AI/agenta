Agenta ships one set of self-hosted images, and a hosted service:

- **Self-hosted**: everyone runs the same public images. A [license key](/self-host/license-keys) decides the plan of the instance.
- **Agenta Cloud** is the hosted service. Its features depend on the plan.

This page lists what differs between them.

## Licensing

The repository at [github.com/Agenta-AI/agenta](https://github.com/Agenta-AI/agenta) contains two kinds of code:

- Everything outside the `ee/` directories is licensed under the **MIT license**. You can self-host it, modify it, and use it in commercial products without restrictions. This includes all SDKs and client libraries.
- Code inside the `ee/` directories is source-available under the **Agenta Enterprise License**. It holds the license key check, the plans and their limits, and the enterprise features.

The self-hosted images contain both. The Agenta Enterprise License allows production use free of charge under the Community plan and the Registered plan, for the features those plans make available. Any other production use, including a feature that needs an Enterprise key, needs an agreement with Agenta and a valid Agenta Enterprise License. You can read and modify the `ee/` code for development and testing.

## Feature availability

Every product feature is available on every plan. Every self-hosted plan and Agenta Cloud have the same prompt management, tracing, evaluation, agents, channels, MCP gateway and secrets. The plans differ in governance (SSO per organization, roles, audit log) and in how many projects and organizations an instance can hold.

The image is the same on every plan. The license key decides the plan:

- **No key**: the Community plan. An expired key, or a key that is not valid, also puts the instance on this plan.
- **Free key**: the Registered plan, from the [free registration key](/self-host/license-keys#get-a-free-registration-key). The free key works only on the instance that registered for it.
- **Enterprise key**: the Enterprise plan, from a key you buy.

You do not change images or databases to move from one plan to another. If your instance runs a version older than v0.131.1, [upgrade it](/self-host/upgrading#upgrading-to-0131-1) first.

### Projects

| Feature | No key | Free key | Enterprise key | Agenta Cloud |
|---|---|---|---|---|
| Projects per organization | 1 | No limit | No limit | 1 on the Hobby plan, no limit on paid plans |

An organization that already has more projects keeps them. The limit only refuses new projects. At the project limit, the [instance admin](/self-host/license-keys#in-the-app) (the person who manages the instance license) gets **Register this instance**, which asks for the free key in place. Other people are told to ask their instance admin.

### Organizations

| Feature | No key | Free key | Enterprise key | Agenta Cloud |
|---|---|---|---|---|
| Organizations per instance | 1 | 1 | No limit | Not applicable |

An instance that already has more organizations keeps them. The limit only refuses new organizations. The first person who signs up gets the organization. After that, a person who signs up gets no organization of their own and joins an existing one by invitation. See [Restrict sign-ups and organization creation](/self-host/guides/restrict-organization-creation#one-organization-without-a-paid-key).

### Roles

| Feature | No key | Free key | Enterprise key | Agenta Cloud |
|---|---|---|---|---|
| Owner, admin and member | Yes | Yes | Yes | Yes |
| Developer, editor, annotator and viewer | No | No | Yes | Business and Enterprise plans |

Without an Enterprise key, invitations and role changes offer admin and member. Members who already have another role keep it.

### Governance

| Feature | No key | Free key | Enterprise key | Agenta Cloud |
|---|---|---|---|---|
| SSO login set up with environment variables | Yes | Yes | Yes | Not applicable |
| SSO providers per organization, set up in the app | No | No | Yes | Business and Enterprise plans |
| Sign-in method enforcement per organization | No | No | Yes | Business and Enterprise plans |
| Domain verification | No | No | Yes | Business and Enterprise plans |
| Audit log | No | No | Yes | Business and Enterprise plans |

Without an Enterprise key, the **Access & Security** and **Audit Log** settings show the enterprise features as locked.

### Authentication and single sign-on

Every self-hosted plan supports email and password login, email one-time codes, and the login providers that you configure with environment variables. The built-in providers include Google, GitHub, Okta, Azure AD, GitLab and others, plus SAML through BoxyHQ. See [Configure SSO](/self-host/guides/configure-sso).

The Enterprise plan adds SSO per organization: each organization sets up its own OIDC provider in the app, verifies its email domain through DNS, and decides which sign-in methods its members may use.

### Audit logs

Audit logs need the Enterprise plan. The Enterprise plan records who did what across the workspace and provides a screen and an API to search those events.

## Frequently asked questions

### Can I use Agenta in a commercial product?

Yes. The MIT code allows commercial use without restrictions. The self-hosted images also run in production free of charge on the Community plan (no key) and the Registered plan (free key).

### Is there a limit to how many users or applications I can create?

A self-hosted instance has no limit on users or applications. Seat limits and usage quotas exist only on the Agenta Cloud plans. Projects and organizations have limits without an Enterprise key. See [Projects](#projects) and [Organizations](#organizations). An Enterprise key can name a number of seats. The **License** tab shows a notice when the instance has more users, but it does not block them.

### If I contribute code to Agenta, what license will it be under?

Contributions outside the `ee/` directories are licensed under MIT.

### Can I get professional support?

Community support is available through [GitHub](https://github.com/Agenta-AI/agenta) and [Slack](https://join.slack.com/t/agenta-hq/shared_invite/zt-37pnbp5s6-mbBrPL863d_oLB61GSNFjw). Professional support with SLAs requires a commercial agreement.
