A self-hosted Agenta instance sends a small amount of usage data to Agenta. We use it to learn how many instances run, which versions they use, and which features people use. This page explains what is sent and how to turn it off. It covers self-hosted instances only. For Agenta Cloud, see [Privacy and data handling](/administration/security/privacy).

## What is never sent

Agenta never receives your content, such as prompts, traces, test sets or model outputs. It never receives email addresses, user names, organization or project names, or the address of your instance.

## What is sent

An instance sends three kinds of data. Each one is linked to a random instance id, which the database creates when you install Agenta.

- **An install ping.** A new instance sends one event when its first organization exists. The event carries only the instance id. An instance that upgrades from an older version does not send it.
- **A heartbeat.** Every 12 hours, the instance sends counts and settings: the Agenta version and edition, how you deployed it (for example Docker Compose or Helm), and the number of users, projects and workflows. It also counts the activity since the last heartbeat, such as traces, evaluations and deployments, and lists the most common email domains of your users, never full addresses.
- **Product usage.** When a user creates an application, starts an evaluation or sends traces, the instance records that the action happened. The browser records page views and the setup steps. Users are identified by their id in your database, never by email.

## Turn telemetry off

Set the switch on the API and restart it.

- Docker Compose: add `AGENTA_TELEMETRY_ENABLED=false` to your `.env` file.
- Helm: set `telemetry.enabled: false` in your values file.

With the switch off, the instance sends no heartbeat and no product usage. Only the one-time install ping still runs, because it carries nothing but the instance id.

A paid license key keeps telemetry on, so the switch has no effect on an instance with one, unless your contract exempts it. The free key you get when you register does not change the switch.

## Update check

The instance also checks `https://agenta.ai/releases.json` every 12 hours, so it can tell you when a newer version or a security fix is available. The check sends no data. Turn it off with `AGENTA_UPDATE_CHECK_ENABLED=false`.

## Settings

| Variable | Default | Effect |
|---|---|---|
| `AGENTA_TELEMETRY_ENABLED` | `true` | `false` stops the heartbeat and product usage. |
| `AGENTA_UPDATE_CHECK_ENABLED` | `true` | `false` stops the update check. |
| `AGENTA_DEPLOYMENT_METHOD` | detected | How you deployed Agenta. The compose files, the Helm chart and the Railway template set it. |

All settings are listed in [Configuration](/self-host/configuration#telemetry).
