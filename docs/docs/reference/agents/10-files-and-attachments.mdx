Files enter an agent through session attachments and leave through file events or tool results. The sandbox working directory is separate from the attachment API.

## Upload and reference

Getting a file in front of an agent takes three calls: upload the bytes, reference the returned attachment ID from the session, then invoke the agent in that session.

Both attachment endpoints need a session ID up front. Use your own value matching the session ID contract in [Invoke an agent](/reference/agents/invoke-an-agent#request-body), or run a first invoke without a `session_id` and read the minted one from the `x-ag-session-id` response header.

### 1. Upload

```
POST {AGENTA_HOST}/api/sessions/attachments?project_id={PROJECT_ID}&session_id={SESSION_ID}
```

The body is `multipart/form-data` with two fields:

| Field             | Type   | Required | Description                                                                            |
| ----------------- | ------ | -------- | -------------------------------------------------------------------------------------- |
| `file`            | file   | Yes      | The file part. Its filename and declared media type are read from the part.            |
| `idempotency_key` | string | Yes      | At most 255 characters. Reuse the same value when you retry after a network error.     |

```bash
IDEMPOTENCY_KEY=$(uuidgen)  # reuse the same value when you retry

curl -X POST \
  "https://eu.cloud.agenta.ai/api/sessions/attachments?project_id=019d952f-0000-0000-0000-000000000000&session_id=customer-case-4821" \
  -H "Authorization: ApiKey $AGENTA_API_KEY" \
  -F "file=@report.pdf" \
  -F "idempotency_key=$IDEMPOTENCY_KEY"
```

```json
{
  "count": 1,
  "attachment": {
    "attachment_id": "019d952f-0000-0000-0000-000000000010",
    "filename": "report.pdf",
    "media_type": "application/pdf",
    "size": 48213,
    "created_at": "2026-10-06T10:00:00Z"
  }
}
```

Omitting the `session_id` query parameter returns `422`. Omitting the `idempotency_key` form field returns an error naming the missing field. The request must carry a `Content-Length` header, which curl sets for you.

### 2. Reference

```
POST {AGENTA_HOST}/api/sessions/attachments/reference?project_id={PROJECT_ID}
```

```bash
curl -X POST \
  "https://eu.cloud.agenta.ai/api/sessions/attachments/reference?project_id=019d952f-0000-0000-0000-000000000000" \
  -H "Authorization: ApiKey $AGENTA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "session_id": "customer-case-4821",
    "attachment_ids": ["019d952f-0000-0000-0000-000000000010"]
  }'
```

The response echoes the referenced attachments. The request accepts at most 100 attachment IDs. The API validates project access before exposing file content to a session.

### 3. Invoke

Send the next turn in the same session. The full request contract is in [Invoke an agent](/reference/agents/invoke-an-agent).

```bash
curl -X POST \
  "https://eu.cloud.agenta.ai/services/agent/v0/invoke?project_id=019d952f-0000-0000-0000-000000000000" \
  -H "Authorization: ApiKey $AGENTA_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json" \
  -d '{
    "session_id": "customer-case-4821",
    "references": {
      "workflow_revision": { "id": "019d952f-0000-0000-0000-000000000002" }
    },
    "data": {
      "inputs": {
        "messages": [
          { "role": "user", "content": "Summarize the attached report." }
        ]
      }
    }
  }'
```

When sending messages, use image or resource blocks with a URI and MIME type, or the equivalent Vercel `file` part. See [Chat message format](/reference/agents/chat-message-format#content-blocks).

## Generated files

An agent can create files in its sandbox. A streamed `file` event carries:

```json
{
  "type": "file",
  "data": {
    "url": "https://example.invalid/download/report.pdf",
    "mediaType": "application/pdf"
  }
}
```

Treat returned URLs according to their expiry and authorization rules. Download files promptly when your application needs durable ownership.

## Working-directory persistence

Files written in the sandbox can persist between turns in the same session, depending on sandbox retention. They are not a substitute for application storage: a cold reconstruction can restore message history without guaranteeing an expired sandbox filesystem.

Do not place credentials in uploaded files or message blocks. Use project secrets, connected applications, MCP secret references, or sandbox credential bindings.
