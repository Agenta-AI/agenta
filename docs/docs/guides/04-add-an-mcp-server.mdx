An MCP server gives your agent tools it can call. You connect the server once to a project, and any agent in that project can use it. To learn how MCP compares with built-in integrations, see [Tools and integrations](/concepts/tools-and-integrations).

:::info Pending release verification
This page describes the MCP connection flow in PR #6049. The steps have not yet been verified against a released build.
:::

## Before you start

Have these ready:

- **The server's HTTP URL**, such as `https://mcp.example.com`. Agenta connects over HTTP. It does not start local processes over stdio.
- **A header name and key**, only if the server authenticates with a header rather than OAuth. You can save the key as a project secret without leaving the connect dialog.

## Connect the server

Start from `Settings` in the sidebar, then `MCPs`, and click `Connect MCP`. You can also start from an agent: open the **MCPs** section of its **Configuration** column, click `Add MCP server`, then click `Connect MCP` in the `Connection` list. Both entry points run the same dialog.

1. Enter the address under `MCP server URL` and click `Continue`. Agenta contacts the server to check that it is reachable and to see how it authenticates.
2. Check the suggested `Name` and edit it if you want. The name labels this connection everywhere you pick it, and it must be unique in the project. Click `Continue`.
3. What comes next depends on what the server reported.

   **The server uses OAuth.** The dialog reads "This server uses OAuth. Continuing opens its authorization page." `Continue` lists the permissions the server offers, one checkbox each, under "Choose which permissions to grant". Clear any you do not want to grant, then click `Authorize`. The provider's consent page opens in a new window. Complete it there, and the dialog carries on by itself.

   **The server needs no authentication.** The dialog reads "This server needs no authentication." Click `Continue`.

   **Agenta could not tell.** The dialog repeats what the server said and offers a credential step. Enter the `Header name` the server expects, such as `x-api-key`, then pick the `Project secret` that holds the key. If the project has no secrets yet, click `Create secret` in that list to make one without leaving the dialog. Click `Save credential`. If the server in fact needs nothing, click `Connect without authentication` instead.

4. The dialog reads `Connected` and reports how many tools it found. Click `Done`.

## Give an agent the connection

1. Open the agent's **Configuration** column and find the **MCPs** section.
2. Click `Add MCP server`, then pick the connection under `Connection`.
3. `Status` shows `Ready` when the connection can be used, next to the server URL. `Tool prefix` shows the label the model sees on this server's tools, which the harness renders as `mcp__<prefix>__<tool>`.

The prefix is frozen when you pick the connection. Renaming the connection later does not rename the tools in an agent that is already saved.

## Choose what the agent may do with each tool

Permissions belong to the agent, not to the connection. Two agents can share one server and be allowed different things, which is why the connection drawer in `Settings` lists the tools read-only and sends you here.

In the agent's **MCPs** section, open the server and find `Permissions`.

1. The field starts on "Every tool on this server follows the server's own permission." Click `Set permissions per tool` to decide tool by tool.
2. Set `A tool with no rule of its own` to `Ask`, `Allow`, or `Deny`. This covers every tool you leave without a rule, including one the server starts advertising after you save.
3. Give individual tools their own rule. `Allow` runs the tool without asking, `Ask` pauses the run for you, `Deny` never runs it, and `Inherit` hands the tool back to the default you set in step 2. A row with no rule of its own says what it inherits, such as `Inherits ask`.

To hand the whole server back to one decision, click `Use the server permission instead`. That clears every per-tool rule you set.

Two kinds of row behave differently:

- A tool that the server's tool filter hides reads "Hidden by this server's tool filter" and its control is disabled. A hidden tool is never offered to the model, so it needs no permission. The filter itself is a configuration field, described in [MCP servers](/reference/agents/mcp-servers).
- A rule for a tool the server has stopped advertising appears under "Rules for tools this server no longer advertises". Agenta keeps it, because a server can drop a tool and bring it back, and a dropped rule would let it return under the default from step 2. Click `Remove` to discard the rule on purpose.

:::note
MCP tools are not covered by the `Always auto-approve` checkbox on an approval card. A tool on `Ask` asks every time it runs, so give a tool you run often its own `Allow` rule instead. See [Control what an agent can do](/guides/control-what-an-agent-can-do) for the agent-wide policy these rules sit inside.
:::

## Connect a second account at the same server

Run `Connect MCP` again with the same URL. Agenta suggests a name that does not collide, such as `Acme (secondary)`. The two connections are separate. Each holds its own authorization, and each agent picks one of them by name.

## Rename, disconnect, or remove a connection

Open `Settings > MCPs` and click the row.

- **Rename.** Edit `Name` and click `Save name`. Agents keep using the connection under its existing reference, so a rename changes nothing about what they run.
- **Tools.** The drawer lists the tools the server exposes. The list is read-only. What an agent may call is set in that agent's configuration.
- **Disconnect.** Drops the stored authorization and keeps the connection, its name, and its URL. Agents using it stop working until it is connected again, and one `Connect` restores it.
- **Remove.** Deletes the connection. Agents configured to use it stop working, and connecting the same server again later creates a new connection that those agents do not reference.

## Troubleshooting

**The status reads `Needs authorization`.** The consent flow was abandoned, or the grant was revoked or has expired. Open the row and click `Connect` to authorize it again. The connection keeps its name and every agent reference.

**`Another connection in this project already uses this name.`** Names are compared after every character outside letters, digits, and underscores is replaced with an underscore, so `Acme Tools` and `Acme-Tools` count as the same name. Pick a name that differs by more than punctuation.

**Connected, but the tool list failed.** The credentials were saved. Click `Retry tools`. There is no need to authorize again.

**`This server exposes no tools yet.`** The server answered with an empty tool list. That is not a connection failure.
