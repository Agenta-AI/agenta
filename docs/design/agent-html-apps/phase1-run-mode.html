Agenta · agent HTML apps · phase 1 · implementation plan

Run mode: a plan seven agents can work at once

Phase 1 of the apps plan, cut into lanes with no shared files. One short lane fixes the contracts everyone codes against; six lanes then run in parallel; one integrates. Each lane says which files it owns, what it consumes, what it provides, how it is tested, and when it is done.

Goal and definition of done

An agent asked for a board writes apps/<slug>/ with a manifest; the user opens the entry file, chooses Run, grants read-write, moves a card; board.json changes on the server; the agent reads it next turn. Both hosts, desktop and /m, behind a feature flag that defaults off.

In scope
  • Bridge contract v1: eight file methods, visible, changed, stat, error codes, automatic If-Match
  • Run segment, grant prompt, status strip, Refresh menu with one item, error strip with copy
  • Assembler: CSP, tokens, kit, same-folder scripts inlined, in-folder navigation in place
  • API: ETag on read and list, If-Match on PUT and DELETE, 412 on mismatch
  • agenta-apps skill, create_app, list_starters, the board starter
  • Design kit tokens and agenta-app.css
  • agent-files/.apps/ in the platform instructions and the skill
Out of scope, on purpose
  • The workspace and pane B (phase 2). Run mode lives in today's Files pane and file cards
  • App tiles for manifest folders, error relay to the composer, more starters, canvas, shelf (phase 3)
  • user, location, chat.draft, assets, "Ask agent to refresh" (v1.1)
  • Conditional writes for the agent's own tools
  • Agent-owned starters, promote_app

Done when all of these are true

  • Acceptance script below passes on desktop and /m, light and dark, flag on; with the flag off nothing about HTML preview changed.
  • Unit tests: bridge protocol, path scope, grant store, ETag cache, assembler; API conditional writes both branches; platform ops; instructions.
  • An agent with the skill attached, asked for a board in a fresh session, produces apps/<slug>/app.json via create_app and no hand-written HTML.
  • A concurrent agent write during a user drag ends with both changes in board.json.
  • Lint, tsc and prettier clean on touched files; ruff format and ruff check clean in api and sdks/python.

Steps

  • 1scope.ts. Normalize with a linear scan, no regex backtracking: reject absolute, empty, ./.. segments, backslashes, control chars, percent-encoded dots after decoding; join with dir; result must start with dir + "/". Tests: the field test's traversal cases plus unicode and trailing slashes.
  • 2grants.ts. Key mountId + "|" + dir → level. In-memory map mirrored to sessionStorage under agenta:app-grants; every access wrapped in try/catch. get, set, clear(mountId).
  • 3etags.ts. Map path → etag; set on every successful read, list entry, stat, write result; cleared on remove; invalidate(paths) for changed.
  • 4fsClient.ts. read and list via Fern getMountFiles (read= / path=); exists via list of the parent filtered by name; stat via list of the parent; remove via Fern deleteMountFile with requestOptions.headers["If-Match"]; write via axios.put to /mounts/{id}/files?path= with raw text body, Content-Type: text/plain; charset=utf-8, and If-Match. Map 404 → not_found, 412 → conflict (carry the etag), 413 or local cap → too_large, 403 → read_only, else unavailable. Verify at step start whether Fern's requestOptions forwards headers; if not, delete goes through axios too.
  • 5stub.ts. Installs window.agenta before any app script. Listens for the hello, keeps port2, resolves ready. Each fs.* call posts an FsRequest with an incrementing id and parks a promise; readJSON and writeJSON wrap parse and stringify; failures reject with an Error carrying code. Applies visibility, changed and theme messages: sets agenta.visible, dispatches events on agenta, rewrites the :root token block. Forwards window.error and unhandledrejection as {type: "error"}. Rejects a hello whose v is not 1 with a visible message in the document body.
  • 6host.ts. attach creates a MessageChannel, posts the hello with port2 transferred, then handles requests on port1 only: scope, grant (write and remove need read-write), caps, then fsClient; sends the etag from the cache as If-Match unless force; updates the cache from results; calls onWrite after a successful write or remove. detach closes the port and drops all handlers. Forwards nav and error messages to callbacks.
  • 7Tests. Run the stub in a jsdom window against a fake port; assert request shapes, id matching, concurrent requests, rejection codes, the unknown-version path. Host tests with a mocked fsClient: grant enforcement, scope rejection before any call, If-Match forwarding, conflict mapping, detach ignores late messages.

Done when

  • All six test files green; pnpm --filter @agenta/entities test:unit and check clean.
  • A five-line node script can drive the host against a real local API and read then write a file with a correct If-Match round trip once lane B is up; documented in the PR.
  • No import from React, antd, or @/oss.

Contract
  • GET files?read=p → {path, content, etag}
  • GET files?path=d → entries carry etag (null for folders)
  • PUT files?path=p honours If-Match and If-None-Match: *; success returns {path, size, etag}
  • DELETE files?path=p honours If-Match
  • Mismatch → 412, body {detail: {code: "conflict", etag: current}}; missing object with If-Match → 412 too, etag null
  • No header → unconditional, as today

Steps

  • 1Spike, two hours, first. Does the miniopy-async put_object in the API's lock accept extra headers (If-Match, If-None-Match) and does SeaweedFS honour them? Write a throwaway script against the dev stack. Record the answer in the PR. Either way, ObjectWriteResult.etag and stat_object give ETags.
  • 2storage.py. Add stat_object → {etag, size, last_modified}; extend put_object with if_match/if_none_match. Native path if the spike says yes; otherwise stat, compare, put, and raise PreconditionFailed on mismatch. Return the new etag from put.
  • 3service.py. read_file returns etag alongside content (one stat or the GET response headers if miniopy exposes them; avoid two round trips where possible). list_files populates etag from the listing where the store provides it. write_file and delete_path take the two conditions and translate the store error into MountPreconditionFailed(etag).
  • 4router.py. Read If-Match and If-None-Match headers; map MountPreconditionFailed to 412 in handle_mount_exceptions. Etag fields on the response models.
  • 5Tests. Unit: both storage branches with a fake store; service maps conditions; router returns 412 with the current etag; unconditional path unchanged. Integration, against the dev stack: write, read etag, write with stale etag → 412, write with fresh etag → 200.
  • 6Fern regen from the saved OpenAPI (generate.sh --language typescript --file …; the API is on :8081 behind traefik). Commit only the mounts resource diff.

Done when

  • cd api && py-run-tests green; ruff format and ruff check clean.
  • The integration sequence above passes against the local stack; the spike outcome is written in the PR body.
  • The Files pane's existing upload and delete are unchanged with no headers.
