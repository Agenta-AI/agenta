## 4. Making the thirteen-cell driver the standing regression check

The driver at `~/agenta-qa-evidence/2026-09-03-session-round2/integration-refresh/refresh_live.py`
is 1455 lines and covers thirteen cells. It is the only artifact in this round that checks the
wire, the durable records, the command rows, and a continuation on one run. It lives outside the
repository, so it dies with the evidence folder.

**Where it should live.** Put it in the existing release-gate skill, not in a new one:

```
.agents/skills/agent-release-gate/resources/session_control.py
```

The gate skill is already the home of the portable wire-level harness, it is already symlinked
into `.claude/skills/`, and its `qa_product.py` already owns the three-variable contract. A second
top-level skill would split the QA surface for no gain. Add one line to `PATH_TRIGGERS` in
`resources/path_triggers.py` so a release that touches `services/runner/**`,
`api/oss/src/core/sessions/**`, or `api/oss/src/dbs/postgres/sessions/**` makes the session-control
cells mandatory. That is the mechanism that stops this suite from going dark the way the
acceptance gate did.

**What it needs to be runnable from one line by a Sonnet QA agent.**

1. **Match the gate's env contract.** It reads `AGENTA_BASE`, `AGENTA_ADMIN_KEY`, and
   `QA_OPENAI_API_KEY` at import time and raises `KeyError` on a missing one. Change it to the
   gate's three variables plus the admin key, and fail with a message that names the missing
   variable. Do not add an env-file fallback. A fallback file is how a green run gets recorded
   against the wrong deployment.
2. **Remove the hard-coded project default.** `--project` defaults to
   `agenta-ee-dev-session-integration`, a docker-compose project name on one box. Seven helpers
   (`dc`, `psql`, `runner_log`, `sandbox_procs`, `stream_row`, `record_rows`, `command_rows`)
   shell into `docker compose` and `psql` against it. Split these into an "operator hooks" module
   with one interface, so the driver runs its wire-only cells against any deployment and skips
   the cells that need a shell on the box, the way `qa_product.py` skips `cold2` without
   `--cold2-replace-cmd`. Six cells need no shell at all: `stop-warm`, `double-send`,
   `stale-stop`, `stop-approval`, `sandbox-gone`, `stop-after-finish`.
3. **Emit the gate's result shape.** Print `PASS`, `FAIL`, or `SKIP` per cell with a one-line
   reason, and write `results.json` plus `summary.md` into `./qa-gate-runs/<timestamp>/`. A
   Sonnet agent must not have to read a 1455-line script to say whether the run was green.
4. **Make the ordering deterministic and the run resumable.** The round-two run lost an agent to
   repeated API overloads and the lead finished it by hand. Add `--cells` resume from a written
   `results.json` so a lost agent costs one cell, not the run.
5. **Write the one-line command into the skill.** After the four changes above:

```bash
uv run resources/session_control.py --cells all --harness pi_core --sandbox local
```

6. **State the preconditions in the skill, next to the command.** A Sonnet agent cannot infer
   these: the deployment's vault must hold the OpenAI key for Pi and Codex and the Anthropic key
   for Claude Code; a Daytona run needs a Secrets-capable Daytona key on the runner, and the key
   in most session env files returns 403 on the Secrets endpoint; `pnpm run build:extension` runs
   once in a fresh runner worktree; and editing runner source mid-run makes the file watcher send
   SIGTERM, which releases the owner claims and invalidates any kill control.
7. **Add the seven new cells from section 3 above** in the same file, so the standing check grows
   with the review standard instead of drifting from it.

Until steps 1 to 3 are done, the driver is a one-box artifact, not a regression check, and every
row in section 1 marked "proven" is proven on a tip nobody can re-run from a command.
