# Existing build-kit audit

Checked against release/v0.119.0 at `ebb825d1da345e7bf9741e832d7664a972e6f72e`. This is a code audit, not a claim that a live setup run has passed. The build kit is the existing tool overlay used to configure an agent.

## Each setup action

| Action                                                    | Existing mechanism                                                                                                             | Conclusion for version one                                                                                                                                                                                                                          |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Know what the template still needs                        | First message carries SETUP.md, optional notes, chosen/skipped connections, and pending recipes.                               | No installation-read tool. The loader supplies this context.                                                                                                                                                                                        |
| Inspect saved configuration                               | `read_config`, when included by the ordered-operations catalog, is in the current build kit.                                   | Reuse it. Verify the deployed kit exposes it; do not invent a second read operation.                                                                                                                                                                |
| Ask for customer profile, repository, or timing           | Embedded `request_input`.                                                                                                      | Reuse the existing form and conversation.                                                                                                                                                                                                           |
| Find integration capabilities                             | `discover_tools`.                                                                                                              | Reuse discovery; do not fabricate available action names.                                                                                                                                                                                           |
| Connect an external integration                           | Embedded `request_connection` with `integration`, optional `slug`, and mode.                                                   | Reuse the existing connection UI and callback.                                                                                                                                                                                                      |
| Connect an MCP gateway target                             | `request_connection` accepts `target: {plane: "mcp", name: "server-slug"}` instead of `integration`.                           | Existing support. A package-local key must resolve to a real gateway target; it is not automatically its project slug.                                                                                                                              |
| Register an arbitrary new custom MCP URL                  | Gateway endpoint services and existing connection/settings UI exist; the client tool's target shape carries a name, not a URL. | Do not claim the tool can register an arbitrary URL from these arguments. Use the existing settings flow. A fully agent-driven URL registration tool is not required for version one; if added later, design it as a general connection capability. |
| Collect a custom secret                                   | Embedded `request_secret`. MCP managed authentication stays with the gateway flow.                                             | Reuse secure collection. No credential-requirements list on template options.                                                                                                                                                                       |
| Change own instructions, tools, skills, MCP configuration | `commit_revision`; catalog delta operations accept ordinary agent configuration.                                               | Reuse native schema validation and revision checks. Preserve full-list semantics where applicable.                                                                                                                                                  |
| Import declared skills and copy starter files             | Existing skills and mount services called by backend loader.                                                                   | Complete before handoff. Do not make the model recreate these resources.                                                                                                                                                                            |
| Personalize copied files later                            | Normal workspace read/write tools under the existing sandbox grants.                                                           | Put optional guidance in SETUP.md. No template-file tool.                                                                                                                                                                                           |
| Verify the setup                                          | `test_run`, plus ordinary safe read tools.                                                                                     | Reuse normal permission policy; loader completion is not the verdict of this test.                                                                                                                                                                  |
| Discover event types and configure an automation          | `discover_triggers`, `create_schedule`, `create_subscription`.                                                                 | Existing create operations ask through their normal approval path. Loading only passes recipes.                                                                                                                                                     |
| Inspect or test automations                               | `list_schedules`, `list_subscriptions`, `list_deliveries`, `test_subscription`.                                                | Reuse them for the agent's ordinary follow-up checks.                                                                                                                                                                                               |
| Declare installation ready                                | No such action needed.                                                                                                         | Delete it. This feature ends at first-message acceptance.                                                                                                                                                                                           |
| Create/configure child agents                             | No general create/edit-other-agent operation is present in `DEFAULT_BUILD_KIT_OPS`.                                            | Future requirement, NOT IMPLEMENTED. Do not add template-scoped child tools.                                                                                                                                                                        |

## Backend gaps, not new agent tools

The source-aware loader itself is new backend work. Create-request deduplication must be enforced by existing resource services. Durable first-message deduplication must cover idle sessions as well as queued inputs; the idle branch currently returns `execute` before a pending-input claim. If existing persistence cannot enforce that contract, extend general create/session-input behavior. Neither gap requires an installation lifecycle or a model-visible operation.
