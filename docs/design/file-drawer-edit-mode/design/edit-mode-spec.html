What this reuses
SharedEditor
Same wrapper the prompt fields use: header / footer slots, editorType="borderless" inside the pane, and its state union (filled · focus · typing · readOnly · disabled) maps 1:1 onto the states in the rail. Set disableDebounce — a file buffer wants keystroke-accurate dirty tracking, not the 300ms prompt debounce.
Editor + markdownPlugin
Source ↔ Preview is TOGGLE_MARKDOWN_VIEW / SET_MARKDOWN_VIEW with markdownViewAtom(id) — already built for the prompt editor. The segmented control in the edit bar is a bigger, explicit surface for the same command; the hover toggle stays out of this pane.
Editor codeOnly
Non-markdown text files use editorProps with codeOnly: true and a language, with language resolved from resolveDriveFileKind(path) and the existing editorLanguage util. Markdown toggle is hidden there.
DiffView
Powers "View diff" in the conflict banner — original = the mount's current bytes, modified = the local buffer.
DriveHeader / DriveToolbar
Both take an editing flag. DriveHeader swaps its action cluster for Cancel / Save; DriveToolbar is replaced by the edit bar, so the origin filter, search and visibility toggles can't be touched mid-edit. The tree pane stays mounted but goes inert, so its scroll position and expansion survive.
Mount write API
Save posts the buffer and expects MountFileWrittenResponse; the response's size/mtime refresh the header chip and the tree row without a full drive refetch. Read-only mounts hide Edit entirely.
Rules
Edit is offered only for text kinds (markdown · text · code · json · csv · html) on a writable mount, and only below the size cap the viewer already enforces. ⌘S saves, Esc cancels (routing through the guard when dirty). One file is editable at a time — the drawer never holds two buffers. Closing the drawer, switching origin filter, switching file, and the browser's own unload all hit the same guard. Session-scoped files warn on first edit that the session may be torn down.
