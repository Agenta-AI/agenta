# Approved onboarding preview, 2026-10-07

Design reference: the `Onboarding.dc.html` design in the Claude Design project (live artifact https://claude.ai/artifact/Mi2TWPUpkSWNQS2Y4jHU2v).

The mobile app (`web/mobile/src/features/onboarding/`) builds one flow from it. The earlier name-first and task-first variants, their PostHog experiment, and the standalone model and tools steps are gone. Pixel parity with the design is not a goal. The flow, the hierarchy, the copy, and the behavior are.

- Page: the flow has its own page, `/m/w/<workspace>/p/<project>/onboarding`, titled "Get started". Each step is a path under it: `/onboarding/role` (work type), `/onboarding/source`, `/onboarding/credits`, `/onboarding/templates`, `/onboarding/templates/<template key>` or `/onboarding/templates/scratch` (the focused panel on desktop, its own view on a phone), and `/onboarding/review`. Moving forward adds a history entry, so the browser's Back and Forward walk the steps, and the step slides in from the side its order says. The bare `/onboarding` resumes: it goes to the furthest step the answers open, which is the first question for a new user. A link to a step the answers do not open yet (for example `/review` with no template picked) goes there too.
- Trigger: onboarding is per user. When SuperTokens reports a new user at sign-up, the app saves `agenta:onboarding:pending:<user id>` in local storage (keyed by the Agenta user id from `/profile`). While that mark stands and `NEXT_PUBLIC_AGENTA_ONBOARDING_FLOW_ENABLED` is on, Home replaces itself with `/onboarding` in the same project. A project that already has agents (an invited teammate's) clears the mark and keeps Home. Create clears it. An empty project with no mark shows the normal Home.
- Preview: opening `/onboarding` directly works on any project for anyone. Without a pending mark it is a preview: no analytics.
- Shell: full page, the Agenta wordmark top left, content centered, and four progress dots at the foot of the page. The dots are also the way back: a step already reached opens from its dot, and the last dot returns from review to the templates. There is no Back button and no step label, as in the design. There is no Skip: the user leaves by creating an agent.
- Questions: work type, then how the user heard about Agenta. Twelve chips each (icon and label, no visible key badges); the letter keys A to L still answer, and the flow moves on after a pick. The questions come from one list, `ONBOARDING_QUESTIONS` in `onboardingQuestions.ts`. To add, remove, reorder or reword a question, edit its entry there and nothing else: `id` (the URL segment, the draft key and the analytics `step_key`), `title`, `subtitle`, `dot` (the progress dot's label), `choices` (label and Phosphor icon, at most twelve), `enabled`, and an optional `personProperty` (the PostHog `$set` key). A choice's optional `category` puts that catalog category first under the gallery's Recommended chip; the work-type question uses it. Shown questions run in list order before the credits, templates and review steps. Analytics numbers steps by the whole list, enabled or not, so turning a question off keeps the funnel numbers.
- Credits: the design's wallet. A kicker, "<N> credits, on us", the dollar value, then the yellow wallet card (real spendable balance counted up, the app's credit rate, entrance and pointer tilt with a glare, all off under reduced motion) beside a Ways to pay panel (Agenta credits, ChatGPT, API key). Real data only: the card appears when the organization has the `starter-credits` Vault connection, Agenta's built-in models, or an enforced wallet; the number and dollar figure come from the wallet summary and are left out when it reports none. ChatGPT and the API key open the existing connection dialog and provider drawer. The model is picked from the runnable connections, Agenta credits first. If none can run, the step says so and the creator links back to it.
- Gallery: the API template catalog (`agentTemplatesAtom`), not the design's sample templates. Category chips come from the catalog, with Recommended ordered by the work-type answer. Each row has a tinted glyph tile. The focused template's panel shows what it connects, when it runs, and its steps (the authored example run, else the tools each connection is used for). Start from scratch turns the same panel into the blank creator: icon row, colour swatches with a custom hue slider, a name, and a first message with starter ideas, then Create. There is no separate page for a blank start.
- Template creator ("Review your agent"): the design's split layout. The template's name and instructions show as set, because Create loads the template package with its own; icon and colour, connected apps and the first message are chosen here, beside the dotted live preview. An app chip connects the app on first tap, then toggles it. A new agent gets only the apps the user picked; onboarding adds no tools of its own.
- Create: a blank start writes its instructions into the agent's `AGENTS.md` and its chosen apps as gateway tools, then commits through the shared create path; a template pick passes its key so the package loads. The user lands in the agent's playground with the first message sent (a template with no message starts itself). The design's "Agent ready" and chat screens are not built. The icon saves onto the new agent's workflow artifact (`tags["@ag"].icon`).
- Answers survive a reload or an auth redirect in session storage, keyed per user (`agenta:onboarding:draft:v4:<user id>`), until Create succeeds. The draft holds only what the user chose and typed (the answers by question id, dropped on read when the question or the choice is gone); the step and the focused template live in the URL, and a detour from review to credits carries `?return=review`.
