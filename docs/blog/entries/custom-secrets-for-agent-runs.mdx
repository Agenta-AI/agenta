<Summary>

You can now give an agent credentials and secret without sharing the value in chat. The credentials are saved in an encrypted vault, they can be used by the agent but not read or modified by it.

To give your agent access to a new credential, go to advanced, then either create or attach a pre-existing secret. The agent will get access to it in the next turn.

Additionally, whenever the agent needs a secret it will prompt to create a new secret and attach it to its session.

</Summary>

An agent may need an API token to use a service from a script. Pasting it into the conversation puts the credential alongside the task instructions. Custom secrets give you a separate place to configure it.

## Attach a project secret

Open Advanced in the agent's configuration, then Custom secrets and Attach. Select a text secret or choose Create new. Set the environment variable the tool expects, such as SERVICE_API_TOKEN, and attach it.

The attachment becomes part of the agent's configuration. Agenta supplies the selected secret to its runtime under that variable name. You can refer to the variable in your instructions without writing the value into the conversation.

## Configure a missing credential during a task

If the agent asks you to configure a secret, use Configure on the request card. Create or select the secret and attach it there instead of replying with the credential in chat.

## Know what write-only means

A saved write-only secret is not returned through normal product reads. This does not mean the value is invisible to code running in the agent's sandbox: the runtime receives it so the tool can authenticate. Attach only the credentials the agent needs, and avoid tasks that print or copy them.

Removing an attachment stops including it through that binding in future runs. It does not delete the secret from the project vault or revoke the credential at its provider.
