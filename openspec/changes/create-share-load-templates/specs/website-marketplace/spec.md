## ADDED Requirements

### Requirement: Shared template and author pages

The website SHALL build a template index, per-template pages and per-author pages from versioned catalog metadata and the author registry. Pages SHALL support descriptions, categories, author links and supported image/video metadata. Display values SHALL come from JSON generated by the same Python reader as the API. Marketplace visual implementation SHALL follow Mahmoud's separately supplied website UI designs. Data generation SHALL NOT depend on export or GitHub loading.

#### Scenario: Author with multiple templates

- **WHEN** two catalog templates reference the same author ID
- **THEN** the author page lists both and links to their template pages

### Requirement: Publication boundary

Published template and author pages SHALL derive from merged catalog entries. A preview build MAY include proposed entries; the published site SHALL NOT require pages for authors whose only contribution is an open PR.

#### Scenario: New author in an open PR

- **WHEN** an unmerged PR adds an author and template
- **THEN** a preview may render them, but the published site remains based on its merged catalog

### Requirement: Template selection link

Use this template SHALL select a stable template key in the destination application using the existing deep-link mechanism. A website page SHALL NOT be treated as the package source. Adding a self-hosted destination picker remains a feasibility proposal, not required UI in this change.

#### Scenario: Visitor selects template

- **WHEN** a visitor follows Use this template
- **THEN** the destination app receives the key, resolves its own catalog and follows its existing authentication/project selection and creation flow
