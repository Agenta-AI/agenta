Agent custom secrets — flow and implementation handoff

Milestone one: attach a saved text secret to an agent as an environment variable, from agent configuration or from an agent's request in chat. One shared drawer, ordinary agent revisions, resume as the application boundary.

Flow: where configuration is saved and where the conversation resumes

Chat
Agent calls request_secret; turn pauses
Request card in the dock: Configure / Not now
Request settled once as configured (reference + variable, no value)
Conversation resumes — same session, saved revision. Credentials applied before the agent's next turn.
Attachment drawer
Choose existing text secret or create one; set variable name
1 · Save new secret to project vault (if creating)
2 · Configuration saved — new revision of the target agent variant with the binding
3 · Conversation's configuration updated to the saved revision; drawer closes
Agent configuration
Advanced → Secrets group: + attach / row opens edit / trash removes
Same drawer, same target label
List shows the new row; version badge increments
Takes effect at the next run boundary; may restart processes
Secret creation fails
Nothing attached. Drawer keeps entries, shows error, user retries. Request stays pending.
Saved in vault; not attached
Step 1 done, step 2 failed. Picker locks to the saved secret; Retry attach reuses it. No second create.
Conflict
Step 2 rejected. Banner names the change; Reload configuration refreshes the target, then attach again from the current revision.
Reload before resume
Binding exists, request unsettled. Dock shows "Ready to continue" with Continue; no re-create.
Resume fails
Configured result stands. Transcript shows a run error with Retry run — same saved revision, no create/attach.
Cancel
Not now settles once as cancelled. Marker reads "GitHub token not configured"; agent acknowledges and does not re-ask automatically.

Existing components reused

  • SecretForm + useSecretForm (entity-ui/secret) — the Create new tab, reduced to Name + a single-line masked Value field (format fixed to text, slug derived from the name and not shown).
  • EnhancedDrawer + DrawerFooter — 600px right drawer, back-arrow header with title/subtitle, Cancel/primary footer with a left disclosure slot (same chrome as CreateSecretDrawer).
  • Connection dock pattern (ConnectionDock / ConnectToolWidget) — "The agent is waiting for you" card above the composer owns the actions; the transcript row is a passive marker that becomes the result chip. Cmd/Ctrl+Enter and Escape bindings carry over.
  • Shared client-tool registry and settle mechanism — one settlement per tool-call id, duplicate clicks and multiple mounted views handled as for request_connection.
  • Existing editor save/discard bar for unsaved configuration edits; existing revision commit with base_revision_id and its conflict response.
  • Tokens: six-slot tags (agent = blue, unavailable = amber, saved = green, text format = olive), warning/error/info banners, ink primary buttons, lime focus ring, JetBrains Mono for slugs and variable names.

New components or variants

  • AttachSecretDrawer (entity-ui) — target header, optional "Requested by the agent" block, Choose existing / Create new segmented picker, an optional Environment variable field inline on Create new (placeholder = name derived from the secret name or the agent's proposal) and an Advanced collapsible for renaming when choosing an existing secret or editing, with validation, banners for create-failed / saved-not-attached / conflict / attach-failed, edit and replace modes. Receives the run target and a commitBinding capability from the playground; never imports playground state.
  • SecretPickerList — radio list over project secrets: name + format tag (no slug); JSON rows disabled with "JSON — can't be attached".
  • AgentSecretsSection — a third compact ConfigAccordionSection group ("Secrets", Key icon) inside the existing Advanced section drawer (useModelHarness.advancedDrawerBody, beside Execution environment and Permissions); rows use the ItemRow pattern (avatar, mono variable name, secret name, hover trash, chevron); schema control for agent.sandbox.credentials: header with count and Add secret, rows (name, slug when names collide, variable, unavailable tag), edit/remove actions, inline remove confirmation, loading skeleton and empty state.
  • SecretRequestCard — dock card variant for request_secret: pending (Configure / Not now), configuring, saved, resuming, ready-to-continue (Continue / Not now), permission notice.
  • SecretRequestWidget — transcript marker/result row: "Set up GitHub token below" → "GITHUB_TOKEN attached" / "GitHub token not configured · Set up anyway".
  • Env-name validator shared with the SDK rule set (regex, reserved names, provider/MCP collisions, duplicates on the same agent).

State transitions and action behavior

  • Request card: pending → configuring (drawer open; closing the drawer returns to pending, it is not a cancel) → saved (binding committed, conversation config updated) → resuming (settle configured, submit next run) → done. pending → cancelled via Not now (settle cancelled once). resuming → resumeFailed keeps the configured result; Retry run resubmits the same saved revision. Reload with binding present and request unsettled → recovered; Continue → resuming.
  • Drawer submit: guarded by phase (idle only) and by the conflict banner. Create path: save secret → lock picker to the saved reference → attach. Attach path: commit revision with base_revision_id. Failures return to idle with a banner; the saved reference survives in the drawer for retry. Raw content is cleared the moment the vault accepts it and on close.
  • Target: fixed at open (originating agent/variant for cards, selected agent for configuration). Switching the header selection shows the mismatch note and does not change the target.
  • Unsaved edits: Add secret / Configure show the blocking notice and route to the existing Save / Discard bar; no side-effect save.
  • Config list actions: Edit binding opens the drawer in edit mode (replace secret and/or rename variable, value never shown). Remove uses an inline confirmation (not a modal) and removes only the attachment. Replace secret on an unavailable row is edit mode with a warning and the variable kept.
  • Duplicate events: Attach, Continue, Retry run and Not now are idempotent on status; the dock and marker never both offer actions for the same request.
  • Mobile: single column with Chat / Configure tabs; the drawer is a full-screen sheet; card actions are 40px targets.

Assumptions and open decisions

  • Visuals follow the v0.112.0 warm palette from the design system; the entity-ui drawer and connection dock were read from source, not rendered. The shipped shadcn Button/Drawer skins may differ slightly.
  • Per review: the variable name is derived from the secret (or the agent's proposal) and lives under Advanced; the footer disclosure sentence was removed. The brief asked for that sentence near Save — confirm dropping it is intended.
  • The picker defaults to Choose existing even when the agent asked for a secret. If telemetry shows most requests end in Create new, flip the default when no name-matching text secret exists.
  • Closing the drawer with Cancel returns the card to pending rather than settling the request; only Not now settles it. Confirm this matches the connect-flow contract.
  • Slugs are hidden everywhere in this flow (per review). Two secrets with the same display name are indistinguishable in the picker — decide whether Settings should enforce unique names or the picker should show a disambiguator on collision.
  • Conflict handling reloads the target revision in place and asks the user to attach again; it never merges. If the other user attached the same variable name, validation now flags the duplicate.
  • "Set up anyway" on a cancelled marker opens the configuration-origin drawer; the agent re-asks only when the user sends a new message. Alternative: re-issue the request automatically on attach.
  • Restart consequence copy now appears only in the inline remove confirmation (the edit-mode note was removed per review). Decide whether replace/rename should warn at all.
  • Permission split assumed: attach requires agent-edit + secret-edit; create additionally requires vault write. Copy addresses both cases without naming permissions.
