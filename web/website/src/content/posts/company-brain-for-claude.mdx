Most engineering and product teams that standardize on Claude hit the same context wall within a few months. One developer has a finely tuned `CLAUDE.md` file in their local git worktree, a product manager has uploaded twelve PDFs into a `Claude Project` on `claude.ai`, and a founder has connected ten different Model Context Protocol (MCP) servers to Claude Desktop. Everyone is using Claude, yet no two sessions share the same source of truth.

When a pricing tier changes, an architecture rule is updated, or an engineer discovers why a staging build fails, that lesson stays trapped inside one person's chat history or local checkout. Worse, when developers wire dozens of raw MCP servers directly into `Claude Code` to compensate for missing company context, tool definitions flood the 200K context window and burn through 5-hour session limits before real work even starts.

Giving Claude and `Claude Code` a real **Company Brain** solves both problems. Instead of duplicating static files across projects or burning tokens on raw tool schemas, a Company Brain maintains a single, living layer of organizational knowledge, reusable skills, and governed integrations that every teammate and every agent session can read and update.

Below, we break down why native Claude memory fragments across teams, how to connect a shared Company Brain to `Claude Code`, and the **6 best platforms and open-source tools** to run a Company Brain for Claude in 2026.

## Why Native Claude Projects, `CLAUDE.md`, and Raw MCPs Break Down at Team Scale

Teams often assume Claude already has shared organizational memory because Anthropic ships three features with similar names: conversation memory, `Claude Projects`, and `CLAUDE.md` files in `Claude Code`. In practice, all three are scoped to a single person, a single project workspace, or a single local git checkout.

![Fragmented Native Claude Context vs Unified Company Brain for Claude and Claude Code](/blog/company-brain-for-claude/claude-memory-silos-vs-shared-brain.webp)

### 1. Static `Claude Projects` Drift Apart Across Workstreams

A `Claude Project` lets you upload reference documents and set custom instructions inside a 200K token context window. That works well for one bounded engagement, until the same company knowledge needs to exist across ten projects at once:

- **No project sharing on Pro or Max plans:** Individual Claude Pro ($20/month) and Claude Max ($100 or $200/month) subscriptions include `Claude Code` and unlimited individual Projects, but project sharing and collaboration require moving the organization onto Claude Team ($25 to $30/seat/month, minimum 5 seats) or Enterprise.
- **Silent document drift:** When your pricing sheet, security rubric, ICP positioning, or API conventions live as uploaded files inside twelve separate `Claude Projects`, updating a policy in one project leaves the other eleven answering with outdated rules.
- **No write-back from execution:** A static `Claude Project` cannot autonomously update a shared file when an agent finishes a research task, resolves an incident, or ships a pull request.

### 2. Local `CLAUDE.md` Files Isolate Non-Technical Teammates and Worktrees

In `Claude Code`, memory is plain text: the CLI reads `CLAUDE.md` and modular `.claude/rules/*.md` files from the developer's local checkout at the start of every session, alongside a local auto-memory directory. While `CLAUDE.md` is effective for repository-specific build commands and linting rules, it has three structural limits as a Company Brain:

- **Per-worktree fragmentation:** Local auto-memory in `Claude Code` is scoped to the local project path or git worktree. When an engineer works across multiple worktrees or machines, session learnings fragment unless manually committed and merged.
- **Every added line taxes every session:** Because `CLAUDE.md` is injected into context on every turn, stuffing cross-functional company context into repo Markdown files bloats token usage once files grow past 150 to 200 lines.
- **Invisible outside the terminal:** Product managers, support leads, operations, and executives in Slack or on the web cannot query or collaborate with a `Claude Code` session running on a developer's laptop.

### 3. Wiring 10+ Raw MCPs Directly into `Claude Code` Burns Session Limits

To give `Claude Code` live company context, many developers connect individual MCP servers for Jira, Linear, Slack, Google Drive, Notion, HubSpot, and GitHub directly to their local CLI. That creates a severe context bottleneck:

- **Tool-schema bloat:** Loading dozens of raw MCP tool definitions consumes a large slice of the context window before you type your first prompt.
- **Chained-call timeouts and rate caps:** Asking a cross-tool question forces `Claude Code` to fire dozens of sequential MCP calls to stitch fragments together, rapidly exhausting Claude Pro and Max 5-hour usage windows and hitting desktop tool-call caps.
- **Entity confusion:** Raw MCP search lacks organizational identity resolution. Asking about an engineer named "Jason" across raw connectors frequently pulls ten unrelated CRM leads named Jason instead of the internal team member's architecture docs.

### Step-by-Step: Connecting Your Claude Subscription and Shared Brain in Agenta

### How Native Claude Projects, Skills, and Connectors Work Together

Anthropic gives organizations four native building blocks that can act as a lightweight Company Brain when combined carefully:

- **Shared `Claude Projects` (the "nouns"):** Workspaces with a 200K context window where teams upload reference documents and standing instructions for a specific client, product line, or department. On Team and Enterprise plans, projects can be shared across colleagues with role-based permissions.

On Team and Enterprise, administrators can deploy skills organization-wide.
- **Remote MCP `Connectors`:** Pre-built and custom MCP integrations (Google Drive, Slack, Microsoft 365, SharePoint, Linear, Jira) that allow Claude to fetch live documents during a conversation.

### Where It Shines (and Where Teams Outgrow It)

1. **Shared context must span across Projects without copy-pasting:** Uploading the same core company handbook or pricing deck across a dozen Projects still creates version drift unless paired with a dedicated Company Brain connector or shared file drive.
2. **You need background execution, cron schedules, or webhook triggers:** Native `Claude Projects` are interactive chat workspaces rather than autonomous cloud sandboxes that wake up on a schedule, run bash/git workflows, and write updated reports back to a shared drive.
3. **Per-seat pricing scales steeply for `Claude Code` users:** While Standard Claude Team seats cost $25/seat/month billed annually ($30 monthly, minimum 5 seats), Team Premium seats that include `Claude Code` cost **$150/seat/month**.

## 4. Vortic: Best Automated Session-Learning Memory for `Claude Code`, `Codex`, and `Cursor` Teams

While wiki-based brains focus on top-down documentation, **[Vortic](https://www.getvortic.com/)** (`Company Brain: memory for AI coding teams`) focuses on bottom-up engineering memory: making sure a mistake one developer's coding agent makes on Tuesday automatically becomes a rule every teammate's agent follows on Thursday.

![Vortic Company Brain for AI Coding Teams](/blog/company-brain-for-claude/vortic.webp)

### How Vortic Learns from Past `Claude Code` Sessions

In most engineering teams, when `Claude Code` fails twice on a staging build because `DATABASE_URL` needs to be exported from the staging vault, the developer corrects the agent in chat and closes the terminal. The next day, another teammate's agent hits the exact same error.

Vortic closes that loop in four layers:

1. **Secret-stripped session import:** Developers run a local Node importer (`node companybrain-import.mjs`) that scans past `Claude Code`, `Codex`, and `Cursor` sessions on their machine, strips common secret formats locally before anything leaves the laptop, and previews the list before uploading.
2. **The Librarian (typed rules and lessons with citations):** Vortic's Librarian analyzes indexed GitHub repositories and imported coding sessions to write versioned rules, lessons, processes, and skills. Every record cites the exact session, file, or Linear ticket it came from.
3. **The Reflector (eval-gated skill updates):** When agents repeatedly stumble on the same workflow, the Reflector proposes updates to team skills and rules, applying changes only when they beat the previous version on replay evaluations or receive human approval.
4. **Single HTTP MCP endpoint + 20-server MCP gateway:** Every developer connects `Claude Code` via `claude mcp add`, giving every new session immediate access to team lessons plus up to 20 managed MCP servers behind one endpoint.

## 5. GBrain (`garrytan/gbrain`): Best DIY Open-Source Postgres + Markdown Brain for Local `Claude Code` Builders

For technical founders and staff engineers who want an inspectable, self-hosted knowledge graph wired directly into their local `Claude Code` and `Codex` CLI sessions, **[GBrain](https://github.com/garrytan/gbrain)** is a popular MIT-licensed open-source project (`10.2k+` GitHub stars).

![GBrain Open Source Agent Brain on GitHub](/blog/company-brain-for-claude/gbrain.webp)

### How GBrain Works with Claude Code over MCP

GBrain treats your Company Brain as a collection of structured Markdown pages backed by **PostgreSQL** and **`pgvector`**, exposed to `Claude Code` as a local or remote MCP server:

- **Two-part Markdown page structure:** Every entity page (representing a customer, repository, product feature, person, or architecture decision) is split into a **compiled truth zone** at the top (which gets overwritten when facts change) and an **append-only chronological timeline** at the bottom (which preserves historical context and links).
- **Hybrid vector + keyword search with `RRF`:** GBrain chunks pages, generates vector embeddings, and combines semantic search with PostgreSQL full-text keyword search using Reciprocal Rank Fusion (`RRF`), ensuring `Claude Code` finds exact error codes and customer names alongside conceptual summaries.
- **Drop-in skill packs:** Includes Markdown skill definitions for ingestion, entity enrichment, daily briefings, and cross-reference syncing so `Claude Code` knows how to query and maintain the brain without custom glue code.

### Trade-offs to Consider

GBrain is built for terminal-first engineers who are comfortable provisioning PostgreSQL (or Supabase), running Bun migrations, and managing their own OpenAI/Anthropic API keys. It does not ship with a turnkey cloud sandbox for non-technical teammates or a visual no-code workspace out of the box.
